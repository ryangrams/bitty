# Content to GitHub

Preserve the user's project identity, audience and distribution choice. Inspect existing repositories, domains, support accounts, affiliate links and community destinations before creating duplicates. Do not invent availability, credentials, compatibility, prices or metrics. Load the user's prose skill before writing public copy.

Read [publishing and community](references/publishing.md) for release, domain, support and community decisions. Use the project's explicit source allowlist to package publication. Public firmware must build from distributable inputs only. A rights checkbox records an acknowledgement; it cannot grant rights to a ROM, APK, artwork or trademark.

Make installation the primary task. For USB-capable microcontrollers, evaluate a static HTTPS browser installer with a supported board manifest and Web Serial runtime manager. Explain browser/OS/driver requirements from current primary documentation. Keep user files local to the browser and device. Native engines require firmware updates unless a genuine module runtime exists.

Create tested release automation, source/build provenance, checksums, recovery instructions, concise setup docs and issue forms that ask for reproducible details without proprietary attachments. Distinguish remove/hide from reclaiming flash. Never describe an unfinished endpoint or placeholder binary as a working installer.

Offer a voluntary GitHub star link without gating, rewards, automated starring or mass solicitation. Verify current GitHub rules. Use GitHub Sponsors when the owner has an active profile; owner payout enrollment remains an owner action. Use project-related affiliate links with nearby disclosure, verified products and the required Amazon Associate identification. Disable unconfigured links rather than linking to invented destinations.

Choose community routing per project. Ryan's Bitty work belongs in Studio Upgrade alongside other gizmo projects. Keep broad help and build discussions in Discord and actionable bugs/port specifications in GitHub Issues, cross-linked. Verify destination and permissions before adding channels or posting. Avoid unnecessary channel sprawl. Other projects retain their own explicit choices.

Prepare concrete site/repo changes before seeking a final decision. Domain purchase, terms, account finance and sensitive access still follow the active tool and user authorization rules. Verify deployed URLs and preserve pending owner actions precisely.
